# Daily Report Specification

## 1. Two outputs

Each successful run should generate a detailed Markdown artifact and a concise chat-channel update. Both must represent the same AI assessment.

## 2. Detailed Markdown report

Recommended order:

```text
# Báo cáo dự án hằng ngày — <PROJECT>
Thời điểm ghi nhận
Project Health

## Đánh giá tổng quan
## Tổng quan dự án
## Priority Risks
## Active Delivery Dependency Hotspots
## Dependency Hygiene / Needs Verification
## Since Last Run
## Rule-based Escalation Signals
## PM Actions
## Key Observations
## Deterministic Hotspots
## Nguồn dữ liệu
```

Priority risk entries should show `AI Delivery Risk`, `Rule-based Hint`, impact and factual evidence. This makes disagreement auditable without forcing the AI to copy the heuristic.

## 3. Concise channel message

Keep the channel version operational rather than exhaustive:

```text
🤖 Cập nhật dự án hằng ngày
<date> · <project>

🧠 AI Project Assessment
<health + short assessment>

🔥 Key Risks
<top 3>

🎯 PM Actions
<top 3>

💡 AI Observations
<1-2>

📈 Since Last Run
<material changes only>

🧭 Risk Lifecycle
<pressure trend + important escalations>

📊 Tổng quan dự án
<compact metrics>
```

## 4. Noise control

Do not dump every issue into the chat message. Keep full deterministic evidence in the detailed report/run log. Prefer top risks and actions with high management leverage.

When there is no material change, say so explicitly rather than repeating old transitions.

## 5. Language

Business-facing text may be Vietnamese while stable machine signal names remain English. Avoid awkward mixed wording where a natural Vietnamese phrase exists. Keep Jira issue keys unchanged.

## 6. Links

Issue URLs should be generated by code from trusted Jira base URL + issue key. The LLM should return keys, not hand-construct URLs.
